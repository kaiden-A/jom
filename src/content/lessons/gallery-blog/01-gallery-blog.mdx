## Tech stack: what we use to build this

Now we go into tech stack. **Haa this is pretty wide** — because you can use anything. Laravel works, PHP works, WordPress works. But for simplicity, let's just use **react + expressjs + neon + r2 cloudflare**. Simple and practical.

Why this stack? Because it's **one language** — JavaScript from front to back. You don't have to switch your brain between two different languages.

<TechStackCards />

<Callout variant="note" title="Common question: why not just store photos in the database?">
Because photo files are big and don't belong in a database row. Database for **structured data**, storage for **files**. Two different things, two different places.
</Callout>

## Project structure: mono repo

Last one — **mono repo structure**. Mono repo means **one repo, many apps**. Instead of separating frontend and backend into different repos, we put everything in one:

<RepoTree />

Why? Because React and Express **share the same things**. For example, the `Photo` data shape — both of them need it:

```ts
// packages/shared/src/types.ts
// One "shape" of data shared by web + api
export interface Photo {
  id: number;
  title: string;
  folder: string;
  imageUrl: string; // URL from Cloudflare R2
  createdAt: string;
}
```

If you had two separate repos, every time this data shape changes you'd copy-paste it in two places. One repo — easy, no syncing back and forth.
