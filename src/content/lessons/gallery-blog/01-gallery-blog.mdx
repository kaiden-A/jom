## Tech stack: what we use to build this

Now we go into tech stack. **Haa this is pretty wide** — because you can use anything. Laravel works, PHP works, WordPress works. But for simplicity, let's just use **expressjs + ejs + neon + r2 cloudflare** — one app that renders its own pages and talks to its own database and storage.

Why this stack? Because it's **one language, one app** — JavaScript from back to front, and no separate front-end project to keep in sync. You don't have to switch your brain between two codebases.

<TechStackCards />

<Callout variant="note" title="Common question: why not just store photos in the database?">
Because photo files are big and don't belong in a database row. Database for **structured data**, storage for **files**. Two different things, two different places.
</Callout>

## Project structure: one app, one repo

Last one — the project structure. **One app, one repo.** No separate frontend folder, no API contract to keep in sync:

<RepoTree />

Why one app? Because there's nothing to sync. The pages, the routes, the database schema — they all live in one codebase, get read in one sitting, and ship as one container. The `Photo` shape lives in exactly one place:

```ts
// src/db/schema/photos.ts — the one place the shape lives
export const photos = appSchema.table("photos", {
  id: uuid().primaryKey().defaultRandom(),
  title: text().notNull(),
  imageKey: text(), // R2 object key, never a URL
  createdAt: timestamp({ withTimezone: true }).notNull().defaultNow(),
});
```

The page that lists photos and the route that creates them both go through this schema. One definition, zero drift.
