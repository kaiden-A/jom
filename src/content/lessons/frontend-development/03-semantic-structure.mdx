In lesson 2 we learned the tags that hold *content*. Now we need tags that describe the *shape* of a page.

This is where a lot of beginners reach for `<div>` and never look back. A `<div>` is a generic box — useful, but it says nothing about what's inside. Semantic tags say something.

## The page skeleton

Every HTML page has the same basic shape:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Calorie Calculator</title>
  </head>
  <body>
    <!-- the page goes here -->
  </body>
</html>
```

- `<!doctype html>` tells the browser this is modern HTML.
- `<html lang="en">` says the page is in English. Screen readers use this.
- `<head>` holds information *about* the page: title, character set, viewport, and links to CSS.
- `<body>` holds everything people actually see.
- The `<title>` is the text in the browser tab, not on the page.

<Callout variant="note" title="What is the viewport tag?">
That `<meta name="viewport"...>` line makes mobile browsers use the real screen width instead of pretending to be a tiny desktop. Without it, every phone would show a zoomed-out desktop page. It's one line. Keep it.
</Callout>

## The semantic tags

These are the ones you'll use most:

| Tag | What it means |
| --- | --- |
| `<header>` | The top of a page or section — title, logo, intro |
| `<nav>` | A group of major navigation links |
| `<main>` | The main content of the page. One per page. |
| `<section>` | A thematic group of content, usually with a heading |
| `<article>` | A self-contained piece of content (a post, a card) |
| `<aside>` | Content related to the main thing, but not part of it |
| `<footer>` | The bottom of a page or section |

You can still use `<div>` for a box that's purely for layout. The rule isn't "never use div." It's "use the tag that describes the content, and use div when nothing does."

<Callout variant="haa" title="Haa!">
A `<div>` is like a cardboard box. It's useful, but if someone asks what's inside, "a box" is not a helpful answer. `<header>` says "this is the top of the page." `<nav>` says "these are the main links." That's the whole idea.
</Callout>

## Why semantics matter

- **Accessibility.** Screen readers use landmarks like `<main>` and `<nav>` to jump around the page. A page made of divs is a maze.
- **Readability.** Six months from now, `<header>` and `<footer>` tell you what a section is. `<div class="top-thing">` doesn't.
- **SEO.** Search engines use headings and structure to understand the page.
- **Consistency.** You and every other developer already know what these tags mean.

<Callout variant="warn" title="One main per page">
Use one `<main>` per page. It marks the main content. If you need multiple sections, use `<section>` inside it. A page with three `<main>` elements is confusing to assistive technology.
</Callout>

## The mistakes everyone makes

- **Using `<div>` for every section.** Try `<section>`, `<header>`, `<footer>` first.
- **Using `<section>` without a heading.** A section is a thematic group; give it an `<h2>`.
- **Multiple `<main>` elements.** One per page.
- **A `<nav>` around every link.** `<nav>` is for major navigation, not a single "read more" link.
- **Styling before structure.** If the outline doesn't make sense, no amount of CSS will fix it.
