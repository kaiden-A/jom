Rendering should be pure: take state and props, return JSX. But real apps also need to do things *outside* rendering — save to localStorage, fetch data, start a timer, subscribe to an event.

Those are **side effects**, and React gives you `useEffect` for them.

## The shape of useEffect

```jsx
import { useEffect } from "react";

useEffect(() => {
  // side effect
}, [dependencies]);
```

The function runs **after** the render. The dependency array decides when it runs again:

| Dependencies | When it runs |
| --- | --- |
| `[]` | Once after the first render |
| `[foods]` | After the first render and whenever `foods` changes |
| no array | After every render (usually a mistake) |

## Saving to localStorage

```jsx
function App() {
  const [foods, setFoods] = useState(loadFoods);

  useEffect(() => {
    localStorage.setItem("foods", JSON.stringify(foods));
  }, [foods]);

  // ...
}
```

- The effect runs after render, so it sees the latest `foods`.
- The dependency `[foods]` means "run again when foods changes."
- It also runs once on mount, which writes the initial value. That's usually harmless.

## Loading: use a lazy initializer

For synchronous storage like localStorage, you don't need an effect to load. Pass a function to `useState`:

```jsx
function loadFoods() {
  try {
    const raw = localStorage.getItem("foods");
    if (!raw) return [];
    const parsed = JSON.parse(raw);
    return Array.isArray(parsed) ? parsed : [];
  } catch {
    return [];
  }
}

const [foods, setFoods] = useState(loadFoods);
```

Note: `useState(loadFoods)`, not `useState(loadFoods())`. React calls the function once, on the first render. This avoids an empty first render and a second render after an effect.

<Callout variant="tip" title="Lazy initializer vs effect">
- **Synchronous data** (localStorage, a parsed URL): use a lazy initializer.
- **Asynchronous data** (fetch): use an effect. You'll do that next lesson.
</Callout>

## Cleanup

Some effects need cleanup: timers, event listeners, subscriptions. Return a function:

```jsx
useEffect(() => {
  const id = setInterval(() => {
    console.log("tick");
  }, 1000);

  return () => clearInterval(id);
}, []);
```

React runs the cleanup before the effect runs again and when the component unmounts. If you forget it, timers and listeners pile up.

<Callout variant="note" title="Why does my effect run twice in development?">
`StrictMode` intentionally mounts, unmounts, and remounts components in development to surface missing cleanup. In production, it runs once. If your effect is correct, the double run is harmless. If it creates a duplicate subscription, you found a bug.
</Callout>

## Don't use effects for derived values

```jsx
// Don't:
const [total, setTotal] = useState(0);
useEffect(() => {
  setTotal(foods.reduce((sum, food) => sum + food.calories, 0));
}, [foods]);

// Do:
const total = foods.reduce((sum, food) => sum + food.calories, 0);
```

The second version has no extra render, no extra state, and no way to drift. Effects are for external systems, not for calculations.

## Saving the whole app

You can save the food list and the profile together:

```jsx
useEffect(() => {
  const data = { foods, profile };
  localStorage.setItem("calorie-calculator", JSON.stringify(data));
}, [foods, profile]);
```

And load them with one lazy initializer:

```jsx
function loadState() {
  try {
    const raw = localStorage.getItem("calorie-calculator");
    if (!raw) return { foods: [], profile: null };
    const parsed = JSON.parse(raw);
    return {
      foods: Array.isArray(parsed.foods) ? parsed.foods : [],
      profile: parsed.profile ?? null,
    };
  } catch {
    return { foods: [], profile: null };
  }
}
```

## The mistakes everyone makes

- **Missing dependency array.** The effect runs after every render.
- **Setting state in an effect that depends on that state.** Infinite loop.
- **Using effects for derived values.** Calculate during render.
- **Forgetting cleanup.** Timers and listeners leak.
- **An object in the dependency array.** A new object every render triggers the effect every time. Use primitives or memoize.
- **Assuming localStorage is available.** It can throw in private mode. Try/catch.
- **Saving on every keystroke with no need.** It's fine for a small app, but know it's happening.
- **Reading stale state in an effect.** Include the values you read in the dependency array.
