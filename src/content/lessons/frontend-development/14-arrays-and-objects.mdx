A single variable is fine for one value. But the calculator has a **list** of foods, and each food has several pieces of information. For that, we need arrays and objects.

## Arrays

An array is an ordered list:

```js
const foods = ["Oatmeal", "Chicken and rice", "Greek yogurt"];
```

- Items are separated by commas.
- Indexes start at **0**: `foods[0]` is `"Oatmeal"`.
- `foods.length` is `3`.
- `foods.push("Apple")` adds to the end.
- `foods.includes("Rice")` checks membership.
- `foods.join(", ")` turns it into a string.

```js
console.log(foods[0]);       // "Oatmeal"
console.log(foods.length);   // 3
console.log(foods.at(-1));   // "Greek yogurt"
```

<Callout variant="note" title="const arrays can still change">
`const` stops you from pointing `foods` at a different array. It doesn't stop `foods.push(...)`. The array itself is still mutable. Use `const` for arrays unless you plan to reassign the variable.
</Callout>

## Objects

An object groups related values under named keys:

```js
const meal = {
  name: "Chicken and rice",
  calories: 550,
  protein: 35,
};
```

- Access with dot notation: `meal.name`, `meal.calories`.
- Or bracket notation: `meal["calories"]` — useful when the key is in a variable.
- Add a key: `meal.fat = 12;`.
- Objects can nest: `{ name: "...", macros: { protein: 35, carbs: 60 } }`.

## Arrays of objects

This is the shape of almost every list in every app:

```js
const foods = [
  { name: "Oatmeal", calories: 320, protein: 12 },
  { name: "Chicken and rice", calories: 550, protein: 35 },
  { name: "Greek yogurt", calories: 150, protein: 15 },
];
```

Each item is an object. The array holds the list. To get the first food's calories: `foods[0].calories`.

## Three methods worth knowing now

```js
const names = foods.map((food) => food.name);
// ["Oatmeal", "Chicken and rice", "Greek yogurt"]

const highProtein = foods.filter((food) => food.protein >= 20);
// [{ name: "Chicken and rice", ... }]

const chicken = foods.find((food) => food.name === "Chicken and rice");
// the matching object, or undefined
```

- `map` transforms every item and returns a **new array**.
- `filter` keeps the items that pass a test, as a **new array**.
- `find` returns the **first matching item** (or `undefined`).

None of them change the original array. That's a good thing.

## Destructuring and spread

Two shortcuts you'll see everywhere:

```js
const { name, calories } = foods[0];
// name = "Oatmeal", calories = 320

const copy = [...foods];
// a shallow copy of the array
```

Destructuring pulls properties into variables. Spread (`...`) copies items into a new array or object. We'll use both more in React.

## The mistakes everyone makes

- **Starting at index 1.** Arrays start at 0.
- **Typo in a key.** `food.calorie` returns `undefined` if the key is `calories`.
- **Forgetting that map/filter return new arrays.** They don't change the original.
- **Using `find` when you want all matches.** `find` returns one; `filter` returns all.
- **Mutating while filtering/mapping.** Keep the original intact; return a new value.
- **Assuming an object is ordered.** Arrays have order; object keys mostly don't.
