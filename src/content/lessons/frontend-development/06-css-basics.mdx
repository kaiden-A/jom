HTML gives you structure. CSS decides what that structure looks like: colors, spacing, size, layout, and all the small details that make a page feel finished.

The mental model is simple. CSS is a list of rules:

```css
selector {
  property: value;
}
```

Pick something, say how it should look. That's it.

## Three ways to add CSS

1. **An external file** — the normal way:

```html
<link rel="stylesheet" href="style.css">
```

2. **A `<style>` block** in the head — fine for a small demo or a single page.

3. **Inline styles** — `style="color: red"` on an element. Avoid these. They're hard to reuse and they win fights with your stylesheet.

In the playground below, the CSS panel is your external stylesheet.

## Selectors

```css
p { color: #5d5680; }          /* every paragraph */
.intro { font-size: 18px; }    /* every element with class="intro" */
#page-title { color: #4f46e5; } /* the one element with id="page-title" */
.card p { margin: 0; }          /* paragraphs inside .card */
h1, h2, h3 { line-height: 1.2; } /* a group */
```

- **Element** selectors are broad. Good defaults.
- **Class** selectors are reusable. This is what you'll use most.
- **ID** selectors are unique. Use them for anchors and JavaScript hooks; use classes for styling.
- **Descendant** selectors (`.card p`) target elements inside something else.

## The cascade

When two rules target the same element, the more specific one wins:

```css
p { color: red; }
.intro { color: blue; }
```

An element with `class="intro"` is blue, because a class is more specific than an element. If specificity is equal, the rule that comes **later** wins.

There's also `!important`, which overrides everything. Avoid it. If you need `!important`, the structure is usually fighting you.

<Callout variant="note" title="Inheritance">
Some properties inherit automatically — `color`, `font-family`, `font-size`. Set a font on `body` and most text follows. Other properties don't inherit — `margin`, `padding`, `border`, `display`. You'll get a feel for this quickly.
</Callout>

## The box model

Every element is a box with four layers:

| Layer | What it is |
| --- | --- |
| **Content** | The text or image itself |
| **Padding** | Space inside the box, around the content |
| **Border** | The line around the padding |
| **Margin** | Space outside the box, pushing other elements away |

By default, `width` applies to the content only. Add padding and border, and the box gets wider than you asked for. That's why almost every project starts with:

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

With `border-box`, `width` includes the padding and border. What you set is what you get. It's the single most useful CSS reset line.

## The mistakes everyone makes

- **Missing semicolon.** One missing `;` can break the next line too.
- **Missing closing brace.** The rest of the file disappears.
- **Specificity wars.** You add an id, then `!important`, then another id. Use classes and keep it flat.
- **`height: 100%` doing nothing.** The parent needs a height for a percentage to work. We'll use flex/grid instead.
- **Styling by tag when a class is clearer.** `p { color: ... }` is fine as a default; use `.intro` for exceptions.
- **Forgetting `box-sizing`.** Your widths will lie to you.
