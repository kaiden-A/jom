A lot of "finished" pages are really just the default state. You hover a button and nothing happens. You tab to an input and you can't tell where you are. It works, but it feels dead.

That's what this lesson fixes.

## Pseudo-classes: the states of an element

```css
.btn { /* normal */ }
.btn:hover { /* mouse over */ }
.btn:focus-visible { /* keyboard focus */ }
.btn:active { /* being pressed */ }
.btn:disabled { /* can't be used */ }
```

A few more you'll use:

- `:checked` — a checked checkbox or radio.
- `:invalid` — a form field that fails validation.
- `:first-child` / `:last-child` — position in a group.
- `:nth-child(odd)` — zebra striping, for example.

<Callout variant="warn" title="Never remove focus without replacing it">
`outline: none` is the most common accessibility bug in CSS. If you remove the default focus ring, add a visible one:

```css
.btn:focus-visible {
  outline: 3px solid #4f46e5;
  outline-offset: 2px;
}
```

Keyboard users need to see where they are.
</Callout>

Why `:focus-visible` instead of `:focus`? Because it only shows the ring when the browser thinks focus should be visible — usually keyboard navigation, not a mouse click. It's the best of both worlds.

## Transitions

A transition animates a property between two values:

```css
.btn {
  transition:
    background-color 0.15s ease,
    transform 0.15s ease,
    box-shadow 0.15s ease;
}

.btn:hover {
  transform: translateY(-2px);
  box-shadow: 0 8px 18px -10px rgba(34, 28, 70, 0.5);
}

.btn:active {
  transform: translateY(1px);
  box-shadow: none;
}
```

- Keep transitions short: 120–250ms. Long transitions feel laggy.
- Animate `transform` and `opacity` when you can. They're cheap. Animating `width`, `height`, or `top` can jank.
- Avoid `transition: all`. It transitions things you didn't mean to, including layout properties.

<Callout variant="tip" title="Small lift, big difference">
A 1–2px upward movement plus a soft shadow on hover is enough. You don't need a bounce, a spin, and a color explosion. Subtle reads as "polished"; everything at once reads as "template."
</Callout>

## Inputs and validation

```css
input:focus-visible {
  border-color: #4f46e5;
  box-shadow: 0 0 0 4px #eef0ff;
  outline: none; /* replaced by the ring above */
}

input:invalid:not(:placeholder-shown) {
  border-color: #fb7185;
}
```

The `:not(:placeholder-shown)` part waits until the user has typed something, so the field isn't red before they start. It's a small trick that makes validation feel less aggressive.

## Disabled and loading states

```css
.btn:disabled {
  opacity: 0.55;
  cursor: not-allowed;
  transform: none;
  box-shadow: none;
}
```

A disabled button should look disabled. Don't just leave it looking clickable and wonder why people keep clicking it.

## Reduced motion

Some people get motion sickness from animations. Respect their setting:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

This is one of the few places `!important` is acceptable. You're overriding every animation on purpose.

## The mistakes everyone makes

- **`outline: none` with no replacement.** Invisible keyboard focus.
- **`transition: all`.** It transitions everything, including things you didn't plan.
- **Animating width/height.** It forces layout. Use transform and opacity.
- **Hover-only interactions.** Touch screens don't hover. Critical actions need a click/tap path.
- **No disabled styling.** A disabled button should look disabled.
- **Too much motion.** If everything moves, nothing feels special.
- **Ignoring reduced motion.** It's a real accessibility setting, not a niche one.
