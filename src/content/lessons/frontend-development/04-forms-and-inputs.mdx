Every calculator, search box, login page, and checkout starts the same way: a form. Forms are how a page asks for information.

The good news: HTML gives you most of the behavior for free. Validation, keyboard support, mobile keyboards, autofill — you get all of that by picking the right input type.

## The form element

```html
<form action="/submit" method="post">
  <!-- fields go here -->
  <button type="submit">Save</button>
</form>
```

- `action` is where the data goes when submitted.
- `method` is how it goes: `get` puts data in the URL, `post` sends it in the request body.
- A `<button type="submit">` submits the form.

We're not sending data anywhere yet, so our form will just stay on the page. The JavaScript part will take over the submit event later.

## Labels are not optional

Every input needs a label. A label tells people what the field is for, and it makes the whole text clickable — click "Age" and the age field focuses.

```html
<label for="age">Age</label>
<input id="age" name="age" type="number">
```

The `for` attribute on the label must match the input's `id`. That's the connection. If they don't match, the label is just text.

<Callout variant="warn" title="Placeholder is not a label">
A placeholder disappears as soon as you type, and screen readers don't treat it as a label. Use a real `<label>`. Placeholders are for examples, not names.
</Callout>

## The input types you'll actually use

| Type | Use it for | Example |
| --- | --- | --- |
| `text` | Names, search, short text | `<input type="text">` |
| `number` | Numbers with min/max | `<input type="number" min="1" max="120">` |
| `email` | Email addresses | `<input type="email">` |
| `password` | Hidden text | `<input type="password">` |
| `checkbox` | On/off, multiple choices | `<input type="checkbox">` |
| `radio` | One choice from a group | `<input type="radio">` |
| `range` | A slider | `<input type="range" min="0" max="10">` |
| `date` | A date picker | `<input type="date">` |

Useful attributes:

- `name` — the key sent with the form. Without it, the field's value is ignored.
- `value` — the starting value.
- `required` — the browser refuses to submit an empty field.
- `min` / `max` / `step` — limits and increments for numbers.
- `checked` — a radio or checkbox starts selected.
- `disabled` — can't be used or submitted.

## Groups: fieldset and legend

When several inputs belong together — like a set of radio buttons — wrap them in a `<fieldset>` with a `<legend>`:

```html
<fieldset>
  <legend>Sex</legend>
  <label><input type="radio" name="sex" value="female"> Female</label>
  <label><input type="radio" name="sex" value="male"> Male</label>
</fieldset>
```

The shared `name="sex"` is what makes them a group: only one can be selected at a time. The `value` is what gets submitted.

## The mistakes everyone makes

- **No label.** Placeholders don't count.
- **`for` doesn't match `id`.** The label looks fine but does nothing.
- **No `name` on an input.** The value won't be submitted.
- **`type="text"` for numbers.** You lose the numeric keyboard on phones and built-in validation.
- **Radio buttons with different `name`s.** They'll all be selectable at once.
- **A `<div>` around every field instead of a `<label>`.** Labels are interactive; divs aren't.
- **No `required` on fields that must be filled.** Let the browser help you.
