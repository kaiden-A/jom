The calculator can calculate. But if you add a food and refresh the page, it's gone. Real apps remember.

There are two ideas in this lesson:

1. **State** — the data that changes while the app is running.
2. **Persistence** — storing that data somewhere so it survives a refresh.

They're related, but they're not the same thing.

## State is the source of truth

For our food log, the state is simple:

```js
let foods = [
  { id: 1, name: "Oatmeal", calories: 320 },
  { id: 2, name: "Chicken and rice", calories: 550 },
];
```

Everything else is derived from it:

- The list of rows in the table.
- The total calories.
- The "remaining" number.

Don't store the total as a separate variable that you have to keep in sync. Calculate it from `foods` whenever you render. One source of truth.

## Render from state

A **render function** takes the current state and updates the page to match:

```js
function render() {
  list.replaceChildren();

  for (const food of foods) {
    const item = document.createElement("li");
    item.textContent = `${food.name} — ${food.calories} kcal`;
    list.append(item);
  }

  total.textContent = `${totalCalories()} kcal`;
}
```

Every time the state changes, call `render()`. That's it. This is the primitive version of what React does for you.

<Callout variant="note" title="A preview of React">
In React, you won't write `render()` by hand. You'll change state, and React re-renders the component. But the mental model is identical: **UI is a function of state.** Keep that sentence in your pocket.
</Callout>

## localStorage

`localStorage` is a small key-value store in the browser. It survives refreshes and browser restarts.

```js
localStorage.setItem("foods", JSON.stringify(foods));

const raw = localStorage.getItem("foods");
const saved = raw ? JSON.parse(raw) : [];
```

Three rules:

1. **It stores strings only.** Use `JSON.stringify` to save objects and arrays, `JSON.parse` to read them back.
2. **It's per browser and per device.** It's not a database, and it doesn't sync.
3. **It can throw.** Private mode, full storage, or a corrupted value can break `JSON.parse`. Wrap it in `try/catch`.

```js
function loadFoods() {
  try {
    const raw = localStorage.getItem("foods");
    if (!raw) return [];
    const parsed = JSON.parse(raw);
    return Array.isArray(parsed) ? parsed : [];
  } catch {
    return [];
  }
}

function saveFoods() {
  localStorage.setItem("foods", JSON.stringify(foods));
}
```

Call `saveFoods()` after every change, and `loadFoods()` once at startup.

## The mistakes everyone makes

- **Saving an object without `JSON.stringify`.** localStorage stores `[object Object]`, and parsing it back fails.
- **Parsing corrupt data.** Wrap `JSON.parse` in `try/catch`.
- **Forgetting to render after a state change.** The data is correct; the page is stale.
- **Storing derived values.** Calculate the total from the foods; don't save a second copy that can drift.
- **Assuming localStorage is shared.** It's per browser and device.
- **Using localStorage for secrets.** It's readable by any script on the page.
- **Hitting the 5MB limit.** It's fine for a food log; not for images.
