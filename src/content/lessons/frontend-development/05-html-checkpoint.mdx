## The plan

Our calculator page has five pieces:

1. **Header** — the title and navigation.
2. **Calculator section** — the form from lesson 4.
3. **Results section** — a big number that will show the calorie target.
4. **Food log section** — an "add food" form and a table of what you ate.
5. **Footer** — a small note.

The table is new. Let's cover it quickly.

## Tables, the right way

Tables are for data that belongs in rows and columns — not for layout. A food log is a perfect fit.

```html
<table>
  <caption>Today's food</caption>
  <thead>
    <tr>
      <th scope="col">Food</th>
      <th scope="col">Calories</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Oatmeal</td>
      <td>150</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row">Total</th>
      <td>520</td>
    </tr>
  </tfoot>
</table>
```

- `<caption>` describes the table. It's not just a title; screen readers use it.
- `<thead>`, `<tbody>`, and `<tfoot>` group the header, body, and footer rows.
- `<th>` is a header cell. `scope="col"` says it labels a column; `scope="row"` says it labels a row.
- `<td>` is a normal data cell.

<Callout variant="note" title="Don't use tables for layout">
In the old days people used tables to arrange entire pages. Don't. Tables are for tabular data. For layout, we'll use CSS Grid and Flexbox in the next part.
</Callout>

## Yes, it's ugly

That's the point. You've built a page with:

- A clear document structure.
- Semantic landmarks.
- A complete, accessible form.
- A real data table with a caption and scoped headers.
- A results area that's ready for JavaScript.

Everything that's missing is visual. We'll fix that in part 2 with CSS.

<Callout variant="tip" title="A quick sanity check">
Open the page and press Tab repeatedly. Can you reach every input, radio, select, and button? Does the focus ring show where you are? If yes, your HTML is already more accessible than a lot of websites.
</Callout>

## What to check before moving on

- [ ] One `<h1>`, and `<h2>` for each section.
- [ ] Header, nav, main, two or three sections, footer.
- [ ] Every input has a label with a matching `for`/`id`.
- [ ] Radio buttons share a `name`.
- [ ] The table has a caption, thead, tbody, tfoot, and scoped headers.
- [ ] The result paragraph has an id (we'll grab it with JavaScript later).
