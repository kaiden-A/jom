The database is not a bucket for the UI. It is the only place that can enforce the rules the UI cannot.

A button can be hidden. A Server Action can be called directly. A customer can refresh the page at exactly the wrong moment. The database is the one part of the system that sees every request, every retry, and every race. So the most important rules in Safelight live there, not in a React component.

This phase creates four tables:

1. **`photographs`** — what is for sale.
2. **`orders`** — the historical fact of a purchase.
3. **`download_tokens`** — the ticket that proves an order may download.
4. **`order_events`** — the append-only audit trail.

The admin session tables arrive in lesson 6. For now, focus on the shop.

## Money is an integer

Never store a price as a float. `0.1 + 0.2` is not `0.3`, and a marketplace cannot afford that kind of surprise.

Store **minor units**:

- `RM 180.00` becomes `price_cents = 18000`.
- `RM 180.50` becomes `price_cents = 18050`.
- Format it only at the edge, with `Intl.NumberFormat`.

The order also stores its own `currency`, copied from the photograph when the order is created. If the shop changes its default currency later, old orders keep the currency they were sold in.

<Callout variant="note" title="Price is a snapshot, not a pointer">
A photograph can cost RM 180 today and RM 240 next week. An order created today must remain RM 180 forever. The order row stores `price_cents` and `currency`; it never joins back to the photograph to ask “how much is it now?”
</Callout>

## The state machine

The order status is deliberately small:

```text
pending_payment ──admin verifies──▶ paid ──admin refunds──▶ refunded
       │
       └──admin cancels──▶ cancelled
```

Email status is a separate track:

```text
not_sent ──claim──▶ sending ──Resend──▶ sent
                        │
                        └──failure──▶ failed ──retry──▶ sending
```

Why separate? Because **paid** is a fact about money, and **sent** is a fact about email. A paid order with a failed email is still paid. The customer is entitled to the file; the email is just how they find out.

## The schema

Create `src/db/schema.ts`. Here are the important parts.

```ts
import { sql } from "drizzle-orm";
import {
  bigserial,
  check,
  index,
  integer,
  jsonb,
  pgTable,
  text,
  timestamp,
  uniqueIndex,
  uuid,
} from "drizzle-orm/pg-core";

export const orderStatuses = [
  "pending_payment",
  "paid",
  "cancelled",
  "refunded",
] as const;

export const emailStatuses = ["not_sent", "sending", "sent", "failed"] as const;

export const photographs = pgTable(
  "photographs",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    slug: text("slug").notNull().unique(),
    title: text("title").notNull(),
    description: text("description").notNull().default(""),
    altText: text("alt_text").notNull().default(""),

    priceCents: integer("price_cents").notNull(),
    currency: text("currency").notNull().default("MYR"),

    previewKey: text("preview_key").notNull(),
    thumbKey: text("thumb_key").notNull(),
    blurDataUrl: text("blur_data_url"),

    originalKey: text("original_key").notNull(),
    originalFilename: text("original_filename").notNull(),
    originalMime: text("original_mime").notNull(),
    originalBytes: integer("original_bytes").notNull(),
    width: integer("width").notNull(),
    height: integer("height").notNull(),

    location: text("location"),
    capturedYear: integer("captured_year"),
    camera: text("camera"),

    status: text("status").notNull().default("draft"),
    publishedAt: timestamp("published_at", { withTimezone: true }),

    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (t) => [
    check("photographs_price_non_negative", sql`${t.priceCents} >= 0`),
    check(
      "photographs_status_valid",
      sql`${t.status} in ('draft', 'published', 'archived')`,
    ),
    check(
      "photographs_published_at_required",
      sql`${t.status} <> 'published' or ${t.publishedAt} is not null`,
    ),
    index("photographs_status_published_idx").on(t.status, t.publishedAt),
  ],
);

export const orders = pgTable(
  "orders",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    reference: text("reference").notNull().unique(),

    photographId: uuid("photograph_id")
      .notNull()
      .references(() => photographs.id, { onDelete: "restrict" }),

    customerEmail: text("customer_email").notNull(),

    // Historical snapshot. Never recalculate from the photograph.
    priceCents: integer("price_cents").notNull(),
    currency: text("currency").notNull(),

    status: text("status").notNull().default("pending_payment"),
    emailStatus: text("email_status").notNull().default("not_sent"),
    emailAttempts: integer("email_attempts").notNull().default(0),
    emailLastAttemptAt: timestamp("email_last_attempt_at", {
      withTimezone: true,
    }),
    emailSentAt: timestamp("email_sent_at", { withTimezone: true }),
    emailMessageId: text("email_message_id"),
    emailLastError: text("email_last_error"),

    paidAt: timestamp("paid_at", { withTimezone: true }),
    cancelledAt: timestamp("cancelled_at", { withTimezone: true }),
    refundedAt: timestamp("refunded_at", { withTimezone: true }),

    paymentClaimedAt: timestamp("payment_claimed_at", { withTimezone: true }),
    paymentClaimNote: text("payment_claim_note"),
    adminNote: text("admin_note"),

    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (t) => [
    check("orders_price_non_negative", sql`${t.priceCents} >= 0`),
    check(
      "orders_email_lowercase",
      sql`${t.customerEmail} = lower(${t.customerEmail})`,
    ),
    check(
      "orders_status_valid",
      sql`${t.status} in ('pending_payment', 'paid', 'cancelled', 'refunded')`,
    ),
    check(
      "orders_email_status_valid",
      sql`${t.emailStatus} in ('not_sent', 'sending', 'sent', 'failed')`,
    ),
    check(
      "orders_paid_at_required",
      sql`${t.status} <> 'paid' or ${t.paidAt} is not null`,
    ),
    uniqueIndex("orders_one_pending_per_email_photo")
      .on(sql`lower(${t.customerEmail})`, t.photographId)
      .where(sql`${t.status} = 'pending_payment'`),
    index("orders_status_created_idx").on(t.status, t.createdAt),
  ],
);

export const downloadTokens = pgTable(
  "download_tokens",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    orderId: uuid("order_id")
      .notNull()
      .references(() => orders.id, { onDelete: "cascade" }),

    // Never store the raw token. Only the SHA-256 hash.
    tokenHash: text("token_hash").notNull().unique(),
    expiresAt: timestamp("expires_at", { withTimezone: true }).notNull(),
    revokedAt: timestamp("revoked_at", { withTimezone: true }),
    lastUsedAt: timestamp("last_used_at", { withTimezone: true }),
    useCount: integer("use_count").notNull().default(0),

    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (t) => [
    uniqueIndex("download_tokens_one_active_per_order")
      .on(t.orderId)
      .where(sql`${t.revokedAt} is null`),
    index("download_tokens_order_idx").on(t.orderId),
  ],
);

export const orderEvents = pgTable(
  "order_events",
  {
    id: bigserial("id", { mode: "number" }).primaryKey(),
    orderId: uuid("order_id")
      .notNull()
      .references(() => orders.id, { onDelete: "cascade" }),
    type: text("type").notNull(),
    actor: text("actor").notNull(),
    metadata: jsonb("metadata")
      .$type<Record<string, unknown>>()
      .notNull()
      .default(sql`'{}'::jsonb`),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (t) => [
    check(
      "order_events_actor_valid",
      sql`${t.actor} in ('customer', 'admin', 'system')`,
    ),
    index("order_events_order_created_idx").on(t.orderId, t.createdAt),
  ],
);
```

## Why these constraints matter

### One pending order per email + photograph

```sql
create unique index "orders_one_pending_per_email_photo"
on "orders" using btree (lower("customer_email"), "photograph_id")
where "status" = 'pending_payment';
```

The application tries to reuse an existing pending order. But two requests can arrive at the same time. The partial unique index is the final referee: even if both requests reach the database, only one row can exist.

If the insert loses, the app catches the conflict and returns the existing pending order. The customer sees one order, not two.

### One active download token per order

```sql
create unique index "download_tokens_one_active_per_order"
on "download_tokens" using btree ("order_id")
where "revoked_at" is null;
```

Reissuing a link must revoke the old one first. The database refuses to leave two active tickets for the same order. That makes “the old email still works after a refund” a bug you cannot ship.

### `paid` requires `paid_at`

```sql
check ("orders_paid_at_required" = "status" <> 'paid' or "paid_at" is not null)
```

A paid order without a paid timestamp is a lie. The constraint makes the lie impossible, even if a future route forgets to set it.

### `on delete restrict` on the photograph

A paid order must keep its photograph. The admin can **archive** a photograph, which hides it from the gallery but keeps the original for customers. Deleting a photograph with orders is not allowed. “Delete” is a UI word; the database uses `restrict`.

## Text + check, not a native enum

You will see statuses stored as `text` with a `CHECK` constraint. Why not a Postgres enum?

- Adding a status to a native enum means `ALTER TYPE ... ADD VALUE`, which has transaction and migration quirks.
- A check constraint is a normal migration: drop it, add the new one.
- The TypeScript union (`orderStatuses`) and the SQL check are easy to keep in sync.

The check is the source of truth. The TypeScript union is the developer experience.

## Prove the constraints

Insert a photograph directly (the upload pipeline comes in lesson 8). Then create an order through SQL or a scratch script:

```sql
insert into photographs (
  slug, title, price_cents, currency,
  preview_key, thumb_key, original_key,
  original_filename, original_mime, original_bytes, width, height,
  status, published_at
) values (
  'morning-tanjung-rhu',
  'Morning, Tanjung Rhu',
  18000,
  'MYR',
  'previews/demo/preview.webp',
  'previews/demo/thumb.webp',
  'originals/demo/original.jpg',
  'morning-tanjung-rhu.jpg',
  'image/jpeg',
  4200000,
  6000,
  4000,
  'published',
  now()
);

insert into orders (
  reference, photograph_id, customer_email, price_cents, currency
) values (
  'SF-7K3M9Q2X',
  (select id from photographs where slug = 'morning-tanjung-rhu'),
  'customer@example.com',
  18000,
  'MYR'
);
```

Now try these:

1. Insert a second order for the same email and photograph with `pending_payment`. It should fail on the partial unique index.
2. Change the photograph price to `24000`. The order still says `18000`.
3. Insert an order with `status = 'probably_paid'`. It should fail the check.
4. Insert a second active download token for the same order. It should fail the partial unique index.
5. Try to delete the photograph. It should fail because the order references it.
