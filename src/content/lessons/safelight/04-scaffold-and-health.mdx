The first phase is not a feature. It is a **floor**.

If the app cannot boot without the right environment, if the database client is a mystery, or if nobody can tell whether Neon is reachable, every later bug is harder to find. So we build the smallest possible Next.js app that:

1. installs and typechecks,
2. refuses to boot with bad config,
3. connects to Neon,
4. answers `/api/health` honestly.

No gallery yet. No auth yet. No photos. Just a floor you can stand on.

<Callout variant="note" title="Why not put everything in app/?">
`app/` is for routing and rendering. The order state machine, the R2 adapter, the email sender, and the auth checks live in `lib/` so they can be tested without a browser. If a file mixes “where the page is” with “how a payment is confirmed”, it will be hard to test and easy to bypass.
</Callout>

## Config that refuses to boot

Create `src/lib/config.ts`. Every server module reads config through this file, never `process.env` directly.

```ts
import "server-only";
import { z } from "zod";

const EnvSchema = z.object({
  DATABASE_URL: z.string().url(),
  PUBLIC_BASE_URL: z.string().url(),
  BRAND_NAME: z.string().min(1).default("Safelight"),
  DEFAULT_CURRENCY: z.string().length(3).default("MYR"),
  WATERMARK_TEXT: z.string().min(1).default("© Safelight · Preview"),

  R2_ACCOUNT_ID: z.string().min(1),
  R2_ACCESS_KEY_ID: z.string().min(1),
  R2_SECRET_ACCESS_KEY: z.string().min(1),
  R2_BUCKET: z.string().min(1),

  RESEND_API_KEY: z.string().startsWith("re_"),
  EMAIL_FROM: z.string().min(1),
  EMAIL_REPLY_TO: z.string().email(),
  DISABLE_EMAIL_SENDS: z
    .enum(["true", "false"])
    .default("false")
    .transform((value) => value === "true"),

  WHATSAPP_NUMBER: z.string().regex(/^\d{8,15}$/),
  PAYMENT_INSTRUCTIONS: z.string().min(1),

  ADMIN_EMAIL: z.string().email().optional(),
  ADMIN_PASSWORD: z.string().min(12).optional(),
});

let cached: z.infer<typeof EnvSchema> | undefined;

export function getEnv() {
  if (!cached) {
    const parsed = EnvSchema.safeParse(process.env);
    if (!parsed.success) {
      console.error("Invalid environment variables", parsed.error.flatten().fieldErrors);
      throw new Error("Invalid environment variables");
    }
    cached = parsed.data;
  }
  return cached;
}
```

Three details matter:

- **`server-only`** makes the build fail if a Client Component ever imports this file. Secrets do not belong in the browser.
- **Lazy parsing** (`getEnv()` instead of `export const env = ...`) avoids breaking `next build` when a route is not evaluated. The app still refuses at runtime.
- **`z.enum(["true","false"]).transform(...)`** is deliberate. `z.coerce.boolean()` would turn the string `"false"` into `true`, which is a classic environment-variable bug.

<Callout variant="warn" title="Don't read process.env everywhere">
One config module, one validation point. If a route reads `process.env.R2_BUCKET` directly, it can boot with a typo and fail later inside a request. That is the worst time to find out.
</Callout>

## The database client

Create `src/db/client.ts`:

```ts
import "server-only";
import { attachDatabasePool } from "@vercel/functions";
import { drizzle } from "drizzle-orm/node-postgres";
import { Pool } from "pg";
import * as schema from "@/db/schema";
import { getEnv } from "@/lib/config";

const globalForDb = globalThis as unknown as { __safelightPool?: Pool };

const pool =
  globalForDb.__safelightPool ??
  new Pool({ connectionString: getEnv().DATABASE_URL });

if (process.env.NODE_ENV !== "production") {
  globalForDb.__safelightPool = pool;
}

if (process.env.VERCEL === "1") {
  attachDatabasePool(pool);
}

export const db = drizzle({ client: pool, schema });
```

Why this shape:

- **One pool, reused.** Next.js dev mode reloads modules; without the global cache you can leak connections on every edit.
- **`attachDatabasePool`** is Vercel's helper for closing idle connections before a function suspends. It is only called on Vercel; local Postgres or Neon does not need it.
- **Use the pooled Neon host** (`...-pooler...`) in `DATABASE_URL`. Serverless functions scale out; a direct host will run out of connections.
- **Transactions work.** `pg` gives us the interactive transactions the order state machine needs.

## The health route

Create `src/app/api/health/route.ts`:

```ts
import { sql } from "drizzle-orm";
import { db } from "@/lib/db/client";

export const dynamic = "force-dynamic";

export async function GET() {
  try {
    await db.execute(sql`select 1`);
    return Response.json({ ok: true, db: true });
  } catch {
    return Response.json({ ok: false, db: false }, { status: 503 });
  }
}
```

No stack traces, no connection string, no table names. It answers one question: **can this app reach its database right now?**

## The proxy is not the lock

Next.js 16 renamed Middleware to **Proxy**. Create `src/proxy.ts`:

```ts
import { NextResponse, type NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  const isAdmin = request.nextUrl.pathname.startsWith("/admin");
  const isLogin = request.nextUrl.pathname.startsWith("/admin/login");

  if (isAdmin && !isLogin && !request.cookies.has("safelight_admin")) {
    const url = request.nextUrl.clone();
    url.pathname = "/admin/login";
    return NextResponse.redirect(url);
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/admin/:path*"],
};
```

This is an **optimistic redirect**, not authorization. It only checks whether a cookie exists; it cannot tell whether the session is valid, expired, or revoked. The real check is `requireAdmin()` in lesson 6, called by every admin page, Server Action, and Route Handler.

<Callout variant="haa" title="Haa!">
A cookie is just a note the browser carries. “There is a note” is not the same as “the note is genuine.” The proxy opens the front door; the session check is the bouncer.
</Callout>

<Callout variant="tip" title="Two files, two jobs">
`.env.example` is documentation. `.env.local` is the real thing. If you ever feel tempted to commit `.env.local` to “help a friend”, copy the keys into `.env.example` with fake values instead.
</Callout>

## `drizzle.config.ts`

Create this now; lesson 5 uses it.

```ts
import { config } from "dotenv";
import { defineConfig } from "drizzle-kit";

config({ path: ".env.local" });

export default defineConfig({
  schema: "./src/db/schema.ts",
  out: "./src/db/migrations",
  dialect: "postgresql",
  casing: "snake_case",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

Drizzle Kit does not load Next.js's `.env.local` automatically. The `dotenv` call is what makes `npm run db:generate` see the same database URL the app sees.

## The boot check

Run these in order. Do not skip one because it “looks fine”.

```bash
npm run typecheck
npm run dev
```

Open `http://localhost:3000/api/health`. You want:

```json
{ "ok": true, "db": true }
```

Then try to break it:

1. Stop the dev server.
2. Temporarily remove `DATABASE_URL` from `.env.local`.
3. Start the app again and open a page that calls `getEnv()`.

You should get a clear “Invalid environment variables” error, not a random `undefined` later. Put the value back.
