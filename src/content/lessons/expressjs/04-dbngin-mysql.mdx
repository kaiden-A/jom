Remember the problem from last lesson? Our users lived in an array, and restarting the server wiped them. **A database is memory that survives.**

MySQL is the database; **DBngin** is how we run it without wanting to throw the laptop out the window.

## What is DBngin?

DBngin is a free little app that runs **MySQL, PostgreSQL and Redis locally with one click**. Normally, installing a database server means services, config files and a lot of swearing. DBngin turns that into: press start.

<Callout variant="note" title="Why not the cloud?">
Cloud databases (Neon, PlanetScale, etc.) are great — the gallery blog uses one. But while learning, a local database is better: it's free, it's instant, and you can break it as many times as you want. Later, the same code can point at the cloud by changing a few values.
</Callout>

User `root` with an empty password is the default for a **local** MySQL. It's fine because nothing outside your laptop can reach it. Never, ever do this on a server that's exposed to the internet — production credentials come from environment variables, which you'll see in the next lesson.

## Designing the users table

A database stores data in **tables** — rows and columns, like a spreadsheet that got serious. Our API only needs one table for now:

| Column | Type | Rules |
| ------ | ---- | ----- |
| `id` | `INT` | primary key, auto increment |
| `name` | `VARCHAR(255)` | not null |
| `email` | `VARCHAR(255)` | not null, unique |

And here it is as SQL:

```sql
CREATE TABLE IF NOT EXISTS users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE
);
```

Read it line by line:

- `INT AUTO_INCREMENT` — an integer that fills itself in: 1, 2, 3… You never choose an id, MySQL does.
- `PRIMARY KEY` — the row's unique identity. It's how a row can be found at all.
- `VARCHAR(255)` — text, up to 255 characters.
- `NOT NULL` — this field can't be empty. The database enforces it, not just our code.
- `UNIQUE` — no two rows can share an email. Insert a duplicate and MySQL refuses.

<Callout variant="haa" title="Haa!">
Notice where the rules live. "Name is required" could be checked in Express. But `NOT NULL` and `UNIQUE` are checked by the **database itself** — the last line of defence. Good backends use both: friendly error messages in the API, hard guarantees in the database.
</Callout>
