No pretty UI here. This is the engine room.

## What "fullstack" actually means

You've probably heard the word a hundred times. Let's make it concrete. **Fullstack just means following one piece of data through the whole trip:**

- **Client** — the browser. It asks for things.
- **Server** — our Express app. It listens, decides, and answers.
- **Database** — MySQL. It remembers things.

That's it. Three players, one loop. Everything else is detail.

<Callout variant="note" title="The restaurant analogy">
The client is a customer ordering food. The server is the waiter — takes the order, passes it to the kitchen, brings back the plate. The database is the kitchen: it doesn't talk to customers, it just stores ingredients and follows recipes. You'll see this analogy again inside the code.
</Callout>

## What we'll build across this project

Five lessons, one small but real API — a `users` service. Here's the map:

1. **This lesson** — the fullstack loop in your head.
2. **Meet Express** — what it is, where it came from, and your first server.
3. **Basic API development** — the four HTTP methods and how endpoints are named.
4. **Database with DBngin + MySQL** — installed, running, and ready.
5. **The full code** — all four files, explained line by line, running for real.

By the end, you'll be able to open a browser, hit your own API, and watch data come out of a real database. That moment never gets old.

<Callout variant="tip" title="Why backend first?">
Because every frontend bug is easier to fix when you know what the server was thinking. This project makes the gallery blog's API stop being a mystery.
</Callout>
